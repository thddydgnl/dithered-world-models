## 2. 판정 계산 (규칙 → `analyze_e2.py`)
- **D_v(N)** = success(같은 N의 none) − success(같은 N의 v), 100쌍에 걸쳐 짝 지은 성공률 차다
  - CI: 짝 bootstrap 10,000회, RandomState(0), 백분위 95%(v5 §7.0)
- **OEI** = 확증 지표 `oei_ref_mf`(v3, v4 §6.2)
  - 실행 계획(마지막 elite 평균)의 e에서 첫 반복 무작위 후보(행 0 = 평균 제외)의 평균 e를 뺀 값이다. e = J_v − J_none(비양자화 모델 비용 기준)
  - 칸 값은 episode 평균이다(open-loop라 episode당 계획이 한 번). 음수가 이용이다
  - \|OEI_det\|는 칸 값의 절댓값이다
- **H2c(PushT)**: 6수준(64, 128, 256, 300, 512, 1024)에서 ρ_s(N, \|OEI_det\|) ≥ 0.8이고 ρ_s(N, D_det) ≥ 0.8이면 성립이다
  - Spearman은 동률에 평균 순위를 준다(scipy)
  - H2c 전체는 4과제(mw-push, mw-pick-place, cheetah-run, PushT) 중 3과제 이상이다. 조정자가 합친다
- **보조**(v5 §7.1)
  - ρ_s(D_det, \|OEI_det\|)
  - sh-iter 평탄성: ρ_s(N, \|OEI_sh-iter\|), ρ_s(N, D_sh-iter)
  - 결합 bootstrap: 한 재표본에서 여섯 수준에 같은 쌍 번호를 쓰고 ρ를 다시 계산한다(10,000회, RandomState(0))
- **분해**(기술, v5.1 §8.2, v5.2 §9.1)
  - drift = last_pop_dJ − it0_rand_dJ
  - sel_indep = mf_dJ − last_pop_dJ: 독립 draw판 sel_last다. sh-iter는 실행 계획의 e를 새 draw로 잰다
  - sel_same(elite) = last_elite_dJ − last_pop_dJ: 같은 draw판 sel_last다. top-30을 고른 그 draw 아래의 오차다
  - 항등식: OEI = sel_indep + drift
- H2c′는 두지 않는다(v5.2 §9.1)

## 6. H4b 입력값 (세 과제, E1 자료) — E1 뒤 사전등록(v5 §7.2), 값은 이번에 처음 계산

### 7.5 읽기 (기술)
- **세 손잡이를 함께 보면** DINO-WM PushT에서 det 손상을 가장 크게 움직이는 것은 CEM 반복 수다
  - N: N = 300까지 오르고 평탄하다(§4, H2c PushT 불성립)
  - elite 비율: 단조 관계가 없다
  - opt_steps: 5 → 30에서 +7 → +24%p로 오른다
  - sh-iter는 모든 설정에서 none 수준이다(−6 ~ +4%p)
- **기전과의 관계**: det OEI의 대부분은 drift이고, drift는 반복과 함께 커진다. v5.2 §9.1이 좁힌 기전 문장("반복에 걸쳐 지속되는 오차의 이용")과 같은 방향의 기술 자료다. 기전 문장의 최종 문구는 조정자가 A 최종 보고에서 정한다
- **TD-MPC2 E2 반복 곡선(보고 §5)과 비교**
  - TD-MPC2: det 손상은 반복 수에 거의 무관했다(0.27~0.50). sh-iter 손상이 반복이 늘수록 크게 줄었다. 반복 1회에서는 sh-iter가 det만큼 또는 더 해로웠다
  - DINO-WM: 반대로 det 손상이 반복과 함께 커지고, sh-iter는 반복 5·10·30 모두에서 none 수준이다
  - 두 계열 모두 sh-iter 이득(D_det − D_sh-iter)은 반복이 늘수록 커진다. 다만 커지는 경로가 다르다. TD-MPC2는 sh-iter 쪽 손상이 줄고, DINO-WM은 det 쪽 손상이 늘어난다
  - det drift가 반복과 함께 커지는 것은 두 계열이 같다(TD-MPC2 mw-push: 0 → −46 → −53 → −60)
- **E7(TD-MPC2 실제 kernel)의 "반복 3에서 dither가 해로움"과 비교**
  - E7에서는 반복 3의 DMC에서 int4 dither가 det보다 해로웠다(cheetah −0.041, walker −0.049)
  - DINO-WM의 가장 적은 반복은 5회이고, 여기서 sh-iter는 det보다 낫다(+9%p [3, 16])
  - 반복 1~3회 영역은 DINO-WM에서 재지 않았다. 계획기도 다르다(CEM top-30 대 MPPI). 그래서 두 결과는 모순이 아니고, "적은 반복에서의 dither 해로움"은 DINO-WM 자료로는 확인도 반박도 되지 않는다

## 8. 관찰 (사후, 판정에 쓰지 않음)
- **none 성공률이 N과 함께 오른다**: 51%(64) → 72%(128) → 79%(256) → 83%(300) → 78%(512) → 87%(1024)
  - N = 64에서는 기준 자체가 낮아 det 손상(+7%p)이 작게 잡힌다. det 성공률은 44% → 65%로 N과 함께 오르지만 none보다 늘 낮다
- **sh-iter는 모든 N에서 none 수준이다**(D −6 ~ +3%p). dither의 손상 제거가 N과 무관하게 유지된다
- **sh-iter OEI가 0보다 조금 크다**: N = 128, 256, 512, 1024에서 CI가 0을 넘는다(+0.005 ~ +0.008). 이용과 반대 방향이고 크기는 det의 2~3%다. v4 H2a 규칙(기본 계획기 N = 300에만 적용)을 다른 N에 그대로 대면 sh-iter 조건(CI가 0 포함)은 N = 64·300에서만 맞는다. 참고로만 적는다
- **E4 모의와의 비교**(v5.1 §8.2가 근거로 든 것, E4 보고 5.7절)
  - E4의 CEM·top-30 고정·지속 오차 group에서는 \|OEI\| 비(N 1024/64) 중앙값이 1.72, Spearman(N, 손상) 중앙값이 +1.0이었다
  - PushT det의 \|OEI\|는 1.15배로 그보다 작다. OEI의 약 90%를 차지하는 drift가 거의 평탄하기(1.1배) 때문이다. 선택 성분(sel_indep, sel_same)만 보면 2.1~2.5배다
  - 손상은 N = 300까지 오르고 그 뒤로 평탄하다(ρ_s +0.771)

## 9. 편차와 코드 수정
- **사전등록 계산에서 벗어난 것은 없다.** H2c 판정, 보조 ρ, 결합 bootstrap, 분해는 v5 §7.1·v5.1 §8.2·v5.2 §9.1 그대로다
- **코드 대조 결과**: `analyze_e2.py`의 H2c 계산이 규칙과 다른 곳은 없었다. E2 수치를 계산하기 전에 아래만 고쳤다(판정 계산은 그대로)
  1. 점마다 변형별 n과 `complete`(100짝)를 적고, H2c 블록에 `complete`를 둔다(불완전하면 잠정 표시)
  2. 자료가 없는 절(E2_dinowm_EO)은 JSON과 표에 "실행 대기"로 적는다
  3. 결합 bootstrap에 sh-iter 평탄성 ρ 둘을 더하고(보조), 정의 안 되는 재표본 수를 센다
  4. 기술 열을 더한다: sh-iter sel_same(elite), 보조 OEI(oei_ref_argmin, oei_true_mf), none 성공률
  5. `--csv`, `--family` 출력(계열 합산용 파일)
  6. 불러온 job의 split이 eval6가 아니면 멈춘다
  - 가짜 자료로 세 경로(완전, 일부, 실행 대기)를 시험한 뒤 실제 자료에 돌렸다
  - 결과는 독립 재계산(JSON에서 직접 성공률과 OEI 평균, ρ)과 같았다
- **H4b 코드**: `analyze_e3.near_tie`에 첫 반복 집합(v5 §7.2 보조), 밀도 CI, 사분위, 사후 민감도 옵션을 더했다. 기본 계산(마지막 반복, 300행, np.std)은 바뀌지 않았다. CRN 이득은 `paired_diff`를 그대로 쓴다
- **계산하지 않은 것**: sh-iter의 같은 draw판 sel_last(mf판). 실행 계획을 마지막 반복 draw로 다시 평가해야 하는데(`drift_ref.py --mode mf_same`), 이것은 GPU를 쓴다. 이번 작업은 GPU를 쓰지 않는다. elite판 sel_same과 독립 draw판 sel_indep는 실었다. det의 mf판은 정의상 sel_indep와 같다
- **새 스크립트**: `check_e2n.py`(자료 점검), `h4b_dinowm.py`(H4b 입력), `e2_posthoc_dinowm.py`(사후 짝 대비, §5)
- **EO 절(10-24) 코드**: EO 수치를 계산하기 전(16:32Z)에 EO 코드 경로를 설계와 대조했다. 다르게 계산하는 곳은 없었다
  - EO의 tag(top6·top38·top75, it5·it10)가 job id와 맞는다
  - 각 점의 none이 그 점의 D 기준이다
  - sel_same(elite)은 그 점의 top-k로 잰다
  - 더한 것(판정과 N sweep 수치는 그대로)
    1. "OEI 두 판"의 같은 draw판 `oei_ref_elite` 열
    2. 점마다 sh-iter 이득 D_det − D_sh-iter와 CI
    3. `--family`의 elite·opt_steps 점
    4. `check_e2n.py --man`(EO manifest 점검, 칸마다 opt_steps를 planner 설정에서 읽음)
    5. `e2_posthoc_dinowm.py`의 EO 짝 대비(사후, §7.4)
  - 같은 명령으로 analyze_e2.py를 다시 돌렸다. N sweep의 기존 출력 값이 모두 같음을 이전 JSON과 비교해 확인했다(차이 0)
- **운영**
  - GPU는 쓰지 않았다. 서버 python은 모두 `CUDA_VISIBLE_DEVICES=""`, `nice -n 10`, OMP·MKL·OPENBLAS 스레드 4로, 한 번에 한 프로세스씩 돌렸다
  - 돌고 있는 사슬·queue·MPS·manifest·claims·결과 폴더는 읽기만 했다. 분석 출력은 서버 `~/pmx/A/dinowm_main/analysis/E2_dinowm/`에 썼다
  - E2 첫 job(N1024) 동안 E1 v5.2 계산(drift_ref·mf_same, PushT k=3·5, 10-22T19:04~19:14Z)이 GPU 1을 같이 썼다. 계획은 결정적이라 결과에는 영향이 없고 GPU 시간만 조금 부풀었다
