### 3.3 두 모드와 GPU clock·호스트 부하

- **두 모드가 다시 나왔다.**
  - 960 block 중 19.2%가 같은 조건의 보통 block보다 15% 넘게 느리다(느린 block의 비 중앙값 1.33, 10~90% 1.27~1.38). 3.3%는 15% 넘게 빠르다.
  - fp32·bf16 block도 17.5%가 느리다. dither와 무관한 측정 환경의 모드다.
- 시간 분포
  - 느린 block은 측정 내내 흩어져 있다. 127번 나타났고, 평균 1.4 block, 가장 길게 5 block 이어졌다.
  - 회전마다 6~27%다. 여섯째·일곱째 회전(시작 뒤 약 47~66분)에 적다.
  - 그림: `posthoc_latency_modes.png`
- **SM clock**(block 끝 읽음)
  - 1,890MHz 아래로 떨어진 block은 10.9%이고, 그 81%가 느린 모드다. 1,890 이상인 block의 느린 비율은 11.6%다.
  - 느린 block의 46%가 clock이 떨어져 있었다.
  - 첫 측정도 같은 모양이었다(11.7%, 68%, 10.4%, 46%).
- **호스트 부하**
  - 이번에는 block 비와의 Spearman이 1분 load +0.45, block CPU 사용률 +0.51이다. 첫 측정은 −0.04, +0.12였다.
  - 재측정 때 호스트 load는 16~22로 첫 측정(20~33)보다 낮았다.
- 정리(기술)
  - 느린 모드의 절반가량은 GPU clock 하락과 같이 나타난다. 나머지는 clock이 정상이어도 나타나고, 호스트 CPU 사용과 함께 움직인다.
  - 원인을 하나로 가를 수는 없다. GPU 1의 DINO-WM은 재측정 전에 끝났으므로, 이번 측정의 원인은 아니다.
- **짝 안 모드 엇갈림**
  - 짝의 26.7%(96/360)가 한 block은 느리고 한 block은 빠르다. 이런 짝의 오버헤드가 ±25~35%라서, 회전 10개 중앙값의 bootstrap CI가 넓어진다.
  - 두 block이 모두 빠른 모드인 짝 241개(67%)의 오버헤드: 중앙값 −0.04%, 사분위 −1.4 ~ +1.5%, 5~95% −3.7 ~ +5.3%. 92%가 ±5% 안이다.
  - 조건별 빠른-빠른 짝의 중앙값은 최대 int8 1.3%, int4 2.1%, packed 2.4%다.

### 3.4 "같은 비트에서 dither 추가 지연은 무시할 수준"이라는 서술을 이 자료가 얼마나 받치는가 (근거만 정리, 주장 결정은 하지 않음)

**받치는 근거**
- 짝으로 잰 오버헤드 중앙값이 36조건 모두 ±3.2% 안이고, CI가 35/36조건에서 0을 포함한다.
- 모드 잡음을 뺀 빠른-빠른 짝은 중앙값이 0(−0.04%)이고 92%가 ±5% 안이다.
- 같은 자료의 사전 정의 계산은 모든 조건에서 10% 아래다(최대 9.1%). 첫 측정도 그랬다(최대 6.9%). H5 ①의 사전 정의 판정(첫 측정)과 같은 쪽이다.
- 구조상 dither의 추가 작업은 층·forward마다 난수 벡터 하나다.

**한계**
- 조건 단위 정밀도가 낮다. 짝 중앙값의 95% CI 상한이 10%를 넘는 조건이 36개 중 16개다(최대 35.5%).
- 이것은 dither 때문이 아니라 측정 환경의 두 모드 때문이다(fp32·bf16도 같은 비율로 느린 block을 가짐). 그래도 이 자료만으로 "각 조건에서 10% 넘는 오버헤드가 없다"를 95% 수준으로 보이지는 못한다.
- 합친 중앙값 계산은 두 측정 사이에서 조건마다 몇 %씩 흔들린다(예: pick-place int8 반복 3 −3.2% → +9.1%).

**정리**: 이 자료는 "같은 비트에서 dither의 전형적인 추가 지연은 몇 % 안이고 0과 구별되지 않는다"는 서술을 받친다. 그러나 조건별 상한을 좁게 보이는 데는 측정 잡음이 커서 충분하지 않다. 어떤 문구를 쓸지는 조정자·사용자가 정한다.

### 4.2 "QAT 학습 자체가 모델을 나쁘게 만들었다"를 어느 칸에서 말할 수 있는가 (기술, 기준은 분석 때 정함)

1. **양자화 없이도 나쁘다**: D(QAT+none)의 CI 하한 > 0인 칸은 **11/11**이다. 활성 양자화를 끄고 QAT 가중치만 쓰면 모든 칸에서 원래 모델보다 크게 나쁘다.
2. **학습한 양자화(det)에 맞춰진 탓으로는 설명되지 않는다**
   - QAT 모델 안에서 det가 none보다 낫지 않은 칸이 9/11이다. 차의 CI가 0을 포함하거나 det가 더 나쁘다.
     - 0을 포함: button, door, pick-place, push, window
     - det가 더 나쁨: finger, peg, quadruped, walker
   - 이 9칸에서는 "det 양자화에 맞춘 모델이라 비양자화가 어긋난다"는 해석이 맞지 않는다. 학습이 모델 자체를 망쳤다는 서술과 맞는다.
   - drawer·sweep 2칸은 det가 none보다 낫다(−0.289, −0.178). 여기서는 QAT+none 손상의 일부가 학습·평가의 양자화 불일치일 수 있다.
3. **원래 모델의 det와 비교**(E1, 다른 seed, 기술)
   - QAT+det가 E1 det보다 나쁜 칸이 7/11이다: door, drawer, peg, pick-place, push, window, walker
   - 나은 칸은 3개다: button, finger, quadruped. sweep은 비슷하다.
- 세 기준을 모두 만족하는 칸은 6칸이다: door, peg, pick-place, push, window, walker.
  - 양자화 없이도 나쁘고, det에 맞춰진 흔적이 없고, det 성능도 원래 모델보다 나쁘다.
  - finger·quadruped·button은 QAT+none이 나쁘지만 QAT+det는 원래 모델 det보다 낫다. QAT가 det를 어느 정도 돕는 동시에 모델 자체를 손상한 칸이다.
- 참고(사후): QAT 모델 위의 sh-iter는 none보다 9/11칸에서 유의하게 낫다. walker는 반대다.

### 4.3 DINO-WM QAT와의 대비 (`reports/E5_dinowm.md` §6, PushT k=4, 100 ep)

| | DINO-WM PushT k=4 | TD-MPC2 11칸 |
|---|---|---|
| QAT+none | +27%p [19, 36] | 0.20~0.82, 11/11에서 CI 하한 > 0 |
| QAT+det | +6%p [−1, 13]. E1 det보다 18%p [8, 28] 낫다 | 0.29~0.85. B+det보다 11/11 나쁘고, E1 det보다 7/11 나쁘다 |
| QAT+sh-iter | +22%p [14, 30]. det보다 16%p 나쁘다 | 0.04~0.82. det보다 9/11 낫다 |
| QAT 모델 안 det 대 none | det가 21%p [12, 30] 낫다 | det가 나은 칸 2/11, 나쁜 칸 4/11, 구별 안 됨 5/11 |

- 공통점: 두 계열 모두 QAT 가중치를 비양자화로 쓰면 원래 모델보다 크게 나쁘다.
- DINO-WM은 QAT 모델이 det 양자화에 맞춰져 QAT+det가 원래 모델과 가깝다. 그래서 E5_dinowm 보고는 "det 양자화에 맞춘 모델"로 해석했다.
- TD-MPC2는 det에서도 나쁘고(PTQ B+det보다 11/11 나쁨), det가 none보다 나은 칸이 거의 없다. 사전등록 QAT 설정(20 episode, 5,000 step)에서 학습이 dynamics·reward 모델을 손상한 쪽으로 보인다. v5.3 §10.1의 "약한 기준선" 단서를 받치는 자료다.

## 5. 편차

- 실행 세부는 v5.3 §10.2·§10.3과 같다.
- 지연의 fp32·bf16은 짝이 없어 단일 block 단위로 섞었다. 96조건을 유지하려는 것이고, 오버헤드 계산에는 들어가지 않는다.
- QAT+none·지연 분석 코드는 실행 전에 만들었고, 이후 고치지 않았다.
- `posthoc_check_tdmpc2.py`의 기술 계산(빠른-빠른 짝, SM clock 문턱 1,890MHz, QAT+sh-iter − QAT+none, §4.2의 세 기준)은 결과를 본 뒤 정한 사후 기술이다.
- 점검 중 내 코드 문제 하나를 고쳤다. block CSV의 시각을 6자리로 적어 그림의 시간축이 뭉개졌다. 3자리 소수 epoch 초로 고쳐 다시 만들었다. 원자료와 분석 출력은 그대로다.
